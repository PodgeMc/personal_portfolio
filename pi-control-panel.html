Pi Control Panel V5

A cross-platform Flutter control panel built to monitor and manage my Raspberry Pi server setup from desktop and mobile. The app connects to a Python backend running on the Pi and provides live service checks, system controls, storage information, and media import progress in one dashboard.

Flutter Dart Python Flask Raspberry Pi Linux Tailscale Android Desktop App

Project Overview

Pi Control Panel V5 was built to make my Raspberry Pi server easier to manage without needing to SSH into it every time. Instead of manually checking services or typing commands in the terminal, I can open the app and quickly see the health of the Pi, Plex, the hosted website, connected storage drives, and media import tasks.

The project brings together mobile app development, Linux server management, Python backend development, remote access, and automation. It is designed around a real system I actively use, which made the project practical rather than just a standalone app idea.

Key Features

Service Monitoring

Checks whether Plex, the hosted website, and storage drives are available from one dashboard.

Server Controls

Can restart Plex, restart the website, reboot the Pi, or shut it down using safe app buttons.

Storage Dashboard

Shows connected drives, mount paths, filesystem details, total space, used space, free space, and usage percentage.

Media Import System

Starts a media import script from the app and displays transfer state, progress, speed, ETA, current file, and recent logs.

System Information

Displays hostname, local IP, uptime, CPU temperature, CPU usage, load average, memory usage, and root disk usage.

Persistent Settings

Saves the Pi host/IP, refresh interval, and auto-update preference so the app remembers the setup after closing.

How It Works

The app is split into a Flutter frontend and a Python backend. The Flutter app sends HTTP requests to a Flask server running on the Raspberry Pi. The backend checks services, reads system information, runs approved system commands, and exposes the information back to the app as JSON.

Flutter App

Runs on Android and Linux desktop. It provides the dashboard, buttons, settings, and live status display.

Python Flask API

Runs on the Raspberry Pi and provides endpoints for status checks, service controls, and import progress.

Raspberry Pi Server

Hosts Plex, the portfolio website, storage drives, import scripts, Tailscale, and systemd services.

Backend API

Main Endpoints

  • /status — returns Plex, website, storage, and system health
  • /transfer-status — returns media import progress information
  • /start-import — starts the media import script
  • /restart-plex — restarts the Plex service
  • /restart-website — restarts the Nginx website service
  • /reboot — reboots the Raspberry Pi
  • /shutdown — shuts down the Raspberry Pi

System Services

The backend is designed to run as a systemd service, meaning it can start automatically when the Raspberry Pi boots. This makes the control panel more reliable because the app can reconnect without manually starting the Python server each time.

This was an important part of turning the project from a test app into something closer to a real server management tool.

Local and Remote Access

At home, the app can connect to the Raspberry Pi using its local network address. For remote access, the app can use the Pi’s Tailscale IP address instead. This allows the control panel to work away from home without exposing the backend publicly to the internet.

This setup made the mobile version much more useful because I can turn on Tailscale on my phone, open the app, and connect back to the Pi through a private secure network.

Challenges and Problem Solving

Mobile Networking

The app initially worked only on the local network. Using Tailscale solved the remote access problem without needing to expose the Pi directly online.

HTTP on Android

The Android build needed network configuration changes so it could communicate with the Pi backend over plain local HTTP.

Service Reliability

The backend needed to start automatically on boot so the app would not depend on manually launching the server after every restart.

Transfer Progress

The media import workflow needed a way to expose progress, speed, ETA, current file, and logs back to the app in a readable format.
