Hosting Project

Raspberry Pi Portfolio Server

This project is the foundation of my website. Instead of relying on standard hosting, I decided to run my portfolio on a Raspberry Pi so I could learn more about Linux, deployment, web servers, and the practical side of managing a live system myself.

Raspberry Pi Linux Nginx Remote Access Self Hosting

Project Overview

This website runs from a Raspberry Pi at home. A web server on the Pi serves the site, while a secure public access setup makes it reachable on the internet. The project gave me a way to move beyond static web design and start learning how websites are actually deployed, hosted, and maintained in a real environment.

More than anything, I wanted the site to feel like a system I owned and managed myself rather than something I uploaded once and forgot about.

Key Features

Self Hosted Website

The portfolio is served directly from my own Raspberry Pi rather than a typical hosting platform.

Live Deployment

The project gave me experience with running a real website and updating it as an active system.

Remote Management

I can work on the site and manage the server from another machine through remote tools.

Linux Server Practice

It became a hands-on way to learn about file structure, services, networking, and troubleshooting.

Why I Built It

I did not want my portfolio to be just a collection of files uploaded to a service and left there. I wanted it to feel like a real technical project in its own right. Hosting the site on a Raspberry Pi gave me a reason to explore Linux, learn how web servers behave in practice, and take more ownership over how the site is delivered.

It also made the portfolio more personal. Visitors are not just seeing a design — they are visiting something that I built, deployed, and maintain on my own hardware.

How It Works

Hosting Setup

The website files are stored on the Raspberry Pi and served by Nginx. That means the Pi handles requests for the site directly and acts as the live host for the portfolio.

A secure public access method makes the site reachable online without needing a more traditional hosting provider.

Development Workflow

I can edit files from another computer, push changes back to the Raspberry Pi, and then check the live result in the browser. This gives me a practical workflow for development and deployment.

Technologies Used

  • Raspberry Pi running Linux
  • Nginx web server
  • Secure tunnelling / remote access tools
  • VS Code with Remote SSH
  • HTML, CSS, and a small amount of JavaScript

What I Learned

  • Installing and configuring a web server on Linux
  • Understanding file structure and deployment workflow
  • How secure access tools can expose local services safely
  • Troubleshooting network and configuration issues
  • Designing and maintaining a multi-page website

Why This Project Matters

This project matters because it turns the portfolio itself into part of the portfolio. Instead of only showing finished web pages, it also shows that I am interested in hosting, deployment, Linux administration, and learning how systems work behind the scenes.

It reflects the kind of work I enjoy most: building something practical, improving it over time, and learning by managing a real system rather than only working in theory.

Future Plans

  • Move from temporary public access solutions to a more permanent setup
  • Automate more of the deployment and startup workflow
  • Add more dynamic features to the website over time
  • Explore building a simple admin area for site updates
